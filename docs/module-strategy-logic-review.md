## 算法正确性与有效性检测方法

策略逻辑不能只看规则描述是否完整，还需要分层验证：先验证计算实现是否与定义一致，再验证信号是否真的具备统计优势，最后验证组合运行时是否稳定、可交易、可复现。

### 1. 逻辑正确性检测

| 检测层级 | 检测目标 | 推荐方法 | 通过标准 |
| --- | --- | --- | --- |
| 公式一致性 | 指标计算是否符合策略定义 | 对 ACD、ER、MACD、RSI、布林带、量比、阶段阈值等建立单元测试 | 手工样例、边界样例、第三方基准结果一致 |
| 信号映射 | 指标状态是否映射到正确买卖动作 | 构造确定性行情样本，例如 Spring、distribution、金叉、死叉、量价背离 | 预期信号与实际输出完全一致 |
| 边界条件 | 极端行情是否产生错误信号 | 测试缺失数据、停牌、零成交量、涨跌停、窗口不足、异常价格 | 不崩溃，不产生无法解释的高置信度信号 |
| 时间顺序 | 是否存在未来函数 | 所有滚动窗口、训练验证切分、宏观数据发布日期均使用信号日前可得数据 | 任一信号不得引用未来价格、成交量或尚未发布的宏观数据 |
| 参数稳定性 | 阈值变化是否导致信号剧烈翻转 | 对核心阈值做敏感性测试，例如量比 1.3-1.8、RSI 25-35 / 65-75 | 小幅参数扰动不应导致绩效完全失效 |
| 模块集成 | 多策略输出是否一致、可解释 | 检查策略输出字段、置信度范围、信号优先级、冲突处理 | 输出 schema 稳定，冲突信号有明确降权或仲裁规则 |

### 2. 算法有效性检测

| 检测类型 | 检测问题 | 推荐指标 |
| --- | --- | --- |
| 样本内回测 | 策略规则在训练区间是否有收益 | 年化收益、最大回撤、夏普比率、胜率、盈亏比 |
| 样本外验证 | 策略是否具备泛化能力 | Walk-forward 收益、样本外 Sharpe、样本外回撤 |
| 基准比较 | 策略是否优于简单基准 | 相对 buy-and-hold、均线策略、行业指数的超额收益 |
| 成本冲击 | 扣除交易成本后是否仍有效 | 手续费、滑点、冲击成本后的净收益 |
| 稳健性 | 是否依赖特定时间段或个股 | 分年度、分行业、分市值、牛熊震荡行情分组表现 |
| 信号质量 | 单个信号是否有预测价值 | 信号后 1 / 5 / 20 / 60 日收益分布、IC、Rank IC、命中率 |
| 风险暴露 | 收益是否来自隐藏风险因子 | 市场 beta、行业暴露、规模、动量、波动率、流动性暴露 |

### 3. 各模块专项检测重点

| 策略 | 正确性重点 | 有效性重点 |
| --- | --- | --- |
| wyckoff_gann | Spring、distribution、时间窗口、MA20 突破是否按信号日以前数据计算 | Spring 后收益分布、distribution 后回撤概率、7/14/21/30/45/60/90 天窗口是否显著优于随机窗口 |
| band | 7阶段状态机边界、P75 回撤映射、黑名单加权、置信度是否超出预期范围 | 分阶段买卖点收益、持仓周期收益、不同阶段阈值的稳定性 |
| volume_price | 量比、涨跌幅、缩量上涨、量价背离的阈值判断是否准确 | 信号后短中期收益、量价齐升与背离信号的胜率和盈亏比 |
| technical | MACD 金叉死叉、RSI 超买超卖、布林带触碰条件是否无未来函数 | 技术组合信号是否优于单指标信号，是否在震荡市中过度交易 |
| macro | 宏观指标发布日期、滞后期、频率对齐是否正确 | 宏观 regime 与资产收益的条件分布，非典型复苏信号的跨周期表现 |
| sentiment | 情绪数据清洗、去重、时间戳对齐是否正确 | 情绪分位数与未来收益、波动率、成交量之间的关系 |
| dense | 特征标准化、训练验证切分、标签构造是否无泄漏 | 样本外预测能力、特征重要性稳定性、过拟合检测 |
| truth | 真值标签定义、回看窗口与预测窗口是否分离 | 标签与策略收益的一致性、不同标签阈值下的稳定性 |

### 4. 最低验收标准

1. **单元测试通过**：每个指标和信号规则至少覆盖正常样本、边界样本、异常样本。
2. **无未来函数**：所有特征、指标、宏观数据、情绪数据均只能使用信号日可获得的信息。
3. **样本外有效**：策略在 walk-forward 或滚动样本外验证中仍保持正的风险调整收益。
4. **扣费后有效**：加入手续费、滑点、停牌、涨跌停和成交量约束后仍不失效。
5. **分组稳定**：不同年份、行业、市值、市场状态下不存在明显只靠单一区间贡献收益的问题。
6. **可解释一致**：高置信度信号必须能追溯到具体指标、阈值和行情上下文。
7. **上线监控**：实盘或仿真环境持续监控信号频率、胜率、回撤、换手率、数据缺失率和置信度漂移。

### 5. 结论

当前报告只能说明各策略规则在描述层面是自洽的；要证明“算法逻辑正确”，必须通过单元测试、边界测试和无未来函数检查；要证明“算法有效”，必须通过样本外回测、成本冲击、稳健性检验和上线监控。只有同时满足正确性检测和有效性检测，策略才可进入实盘或生产级评估流程。
